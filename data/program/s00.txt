## How this program works

The program starts here, with a diagnostic, so the plan is built on what you can actually do. Then come three strands in this order:

1. **Python 1–6**, the language foundation: core types and their cost, functions and decorators, generators, classes, production habits (errors, context managers, tests) and concurrency. Every exercise is a small data engineering task with real tests.
2. **AI 1–3**, woven between the Python modules: agent loops, harness engineering, prompts that save credits, evals, and agents that review and fix their own work. Each AI module comes after the Python it needs: AI 1 after functions, AI 2 after classes, AI 3 after concurrency.
3. **Modelling 1–3**, data modelling: dimensional modelling (grain, keys, SCD types, cumulative tables, graphs), fact modelling (the four fact types, ledgers, reduced facts, date lists), and the right model for every stage from raw data to semantic layers and feature stores. The exercises are SQL, which you already know well.
4. **DE 1–12**, the data engineering modules, built on one platform. Three modules sit inside this stretch, added from current tier-1 job postings: **Systems 1** after DE 4 (distributed systems and storage internals: the "why" behind every tool), **Platform 1** after DE 7 (reading Scala, the JVM, Kubernetes and Hadoop) and **Leadership 1** after DE 10 (design docs, strategy, migrations, cost, influence and the behavioural round).

After DE 12, **Extra** modules arrive every week: one big-tech engineering problem or research paper, plus new questions on earlier topics.

Problems you struggle with (you open the solution, need two or more hints, or need three or more runs) join a **review queue**. They come back on the coding card after 3, then 7, then 21 days, starting from a blank editor each time. This is how you keep what you learn until the interview.

Time is boxed, not the modules. The plan gives you **60 minutes on weekdays and 120 on Saturday and Sunday** (change both in Settings). Each module is split into steps that fit one day. Anything you do not finish moves to the next free day, so a module takes as many weeks as it needs and the dates on Today and Path always stay true. Coding practice (DSA, SQL, PySpark and the timed coding tests) runs on its own track, outside that hour.

You play the first data engineer at **Meridian**, a fictional ride-hailing and food-delivery company operating in Indian cities. Each module the business asks for something. Delivering it needs several technologies working together, and at some point something breaks. The interview material is attached to that work: you learn Spark tuning because your job is slow, and watermarks because surge pricing is using stale data.

Ride-hailing was chosen on purpose. In your question bank, Uber, Meta, Google and Grab all use it for data modeling and system design rounds. By DE 10 you will have built the system those rounds ask you to design.

## Two rules about using AI

1. **Tests are done with AI off.** Quizzes and coding tests measure what you can do alone, because some companies ban AI in interviews and all of them ask follow-up questions.
2. **Builds are done with AI on, and you must be able to explain every line.** Other companies now grade how well you direct an assistant and whether you catch its mistakes. Treat generated code as a pull request from a junior engineer: read it, run it, and reject what you cannot defend.

## How scoring works

- Multiple-choice and fill-in questions mark themselves. Short answers show a model answer and you mark yourself: I got it, or not yet.
- Coding problems are checked by real tests in your browser. Hints come one step at a time; the solution unlocks after two runs or 15 minutes.
- A module is ready to close when the quiz is at 80% or better and at least half of the coding problems are solved alone. Below that, revisit the weak sections (search finds any topic with ⌘K or /) before moving on.
- **Progress** adds everything up: steps and hours done, your study streak, the planned finish date, and readiness by interview round (DSA, SQL, PySpark, quizzes, interview sets).

TITLE: Second-highest salary per department
KIND: sql
MIN: 15
TAG: sql
SRC: asked in several loops in your bank
PROBLEM:
Table `emp(emp_id, name, dept, salary)`.

Return `dept, name, salary` for every employee who earns the **second-highest distinct salary** in their department. If two people tie for it, return both. Departments with only one distinct salary return nothing. Order by `dept, name`.
SOLUTION:
```sql
WITH r AS (
  SELECT dept, name, salary,
         DENSE_RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rnk
  FROM emp
)
SELECT dept, name, salary
FROM r
WHERE rnk = 2
ORDER BY dept, name;
```

`DENSE_RANK` is the right function because the question says *distinct* salary and wants ties kept. `ROW_NUMBER` would return one arbitrary person. `RANK` would skip rank 2 when two people share the top salary.

Expect the follow-up: "do it without a window function." Use a correlated subquery that takes the maximum salary below the department maximum.

TITLE: Riders active three days in a row
KIND: sql
MIN: 15
TAG: sql
PROBLEM:
Table `logins(user_id, login_date)`. A user can have several rows for the same date.

Return the `user_id` of every user who logged in on at least **three consecutive calendar days**. Order by `user_id`.
SOLUTION:
```sql
WITH d AS (
  SELECT DISTINCT user_id, login_date FROM logins
),
g AS (
  SELECT user_id, login_date,
         login_date - CAST(ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) AS INTEGER) AS grp
  FROM d
)
SELECT DISTINCT user_id
FROM g
GROUP BY user_id, grp
HAVING COUNT(*) >= 3
ORDER BY user_id;
```

This is the gaps-and-islands pattern. Within a run of consecutive dates, the date and the row number both increase by one, so their difference is constant. That constant labels the run. De-duplicating first matters, because two rows for one day would break the arithmetic.

Date arithmetic differs by engine. Snowflake uses `DATEADD(day, -rn, login_date)` and Spark SQL uses `date_sub(login_date, rn)`.

TITLE: Longest substring without repeating characters
KIND: dsa
MIN: 15
TAG: dsa
SRC: Stripe, 4 YOE
PROBLEM:
Given a string, return the length of the longest substring that contains no repeated character.

`"abcabcbb"` returns 3. `"bbbbb"` returns 1. `"pwwkew"` returns 3. Aim for one pass.
SOLUTION:
```python
def longest_unique(s: str) -> int:
    last = {}            # character -> index where it was last seen
    start = best = 0
    for i, ch in enumerate(s):
        if ch in last and last[ch] >= start:
            start = last[ch] + 1      # jump the window past the repeat
        last[ch] = i
        best = max(best, i - start + 1)
    return best
```

Sliding window with a hash map. Time O(n), space O(k) for k distinct characters. The check `last[ch] >= start` matters: a character seen before the current window is not a repeat. `"abba"` is the test that catches this.

TITLE: De-duplicate events, then total per user
KIND: pyspark
MIN: 15
TAG: spark
PROBLEM:
A DataFrame `df` has columns `user_id, event_id, ts, amount`. The same `event_id` can arrive more than once with different `ts` values because of retries.

Write `spend_per_user(df)` that keeps only the **latest** row for each `event_id`, then returns `user_id, total` with the sum of `amount` per user, ordered by `user_id`.
SOLUTION:
```python
from pyspark.sql import functions as F, Window

def spend_per_user(df):
    w = Window.partitionBy("event_id").orderBy(F.col("ts").desc())
    latest = (df.withColumn("rn", F.row_number().over(w))
                .filter(F.col("rn") == 1)
                .drop("rn"))
    return (latest.groupBy("user_id")
                  .agg(F.sum("amount").alias("total"))
                  .orderBy("user_id"))
```

`dropDuplicates(["event_id"])` would also remove duplicates, but it keeps an arbitrary row, not the latest. The window makes the choice explicit. Both steps shuffle: one by `event_id`, one by `user_id`. Say that out loud in an interview before you are asked.
