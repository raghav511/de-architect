## C10.1 What MCP is

The **Model Context Protocol** is a standard way to give an AI app new tools. An **MCP server** is a small program that exposes tools (functions with a name, description and input schema), and optionally resources and prompts. Claude Code is the client: it lists the server's tools, and the model can call them like built-in tools, with the same permission prompts.

For data engineers this is the bridge to your stack: a warehouse query tool, the orchestrator's API (DAG status, last run logs), the data catalog (lineage, owners), the ticket system. You met the idea in AI 2; here you use it inside Claude Code.

## C10.2 Adding servers and scopes

```bash
claude mcp add warehouse -- python3 mcp_warehouse.py          # a local server over stdio
claude mcp add --transport http docs https://example.com/mcp   # a remote server over HTTP
claude mcp list                                                # what is configured
```

Inside a session, `/mcp` shows server status and lets you authenticate to remote servers.

| Scope | Flag | Stored in | Use |
|---|---|---|---|
| local | default | your user config, this project only | trying a server |
| project | `--scope project` | `.mcp.json` in the repo (commit it) | team-shared servers |
| user | `--scope user` | your user config, all projects | personal tools |

Every server's tool descriptions are added to the context of every session, so connect only what you use.

## C10.3 A tiny read-only warehouse server

```python
# mcp_warehouse.py  (pip install mcp)
import json, sqlite3
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("warehouse")
DB = "file:warehouse.db?mode=ro"          # read-only at the connection level

@mcp.tool()
def list_tables() -> str:
    """List tables and their columns in the warehouse."""
    con = sqlite3.connect(DB, uri=True)
    out = {t: [c[1] for c in con.execute(f"PRAGMA table_info({t})")]
           for (t,) in con.execute("SELECT name FROM sqlite_master WHERE type='table'")}
    return json.dumps(out)

@mcp.tool()
def query(sql: str, limit: int = 50) -> str:
    """Run a read-only SELECT and return at most `limit` rows as JSON."""
    if not sql.lstrip().lower().startswith(("select", "with")):
        return "Only SELECT queries are allowed."
    con = sqlite3.connect(DB, uri=True)
    rows = con.execute(sql).fetchmany(min(limit, 200))
    return json.dumps(rows)

if __name__ == "__main__":
    mcp.run()
```

The `mode=ro` connection is the real guard; the `startswith` check is only a friendly message. **Enforce read-only in the database**, not in the prompt or the tool text. In a real warehouse: a dedicated role with SELECT only on the schemas the agent needs, row limits, a statement timeout and query tagging, so cost and access are visible.

## C10.4 MCP security

- An MCP server runs with **your** permissions; installing one is installing software. Use servers from sources you trust, and pin versions.
- Tool results are untrusted text: a row or document can contain prompt injection. Combine read access to private data with write or network tools only with great care (that combination is how data gets exfiltrated).
- Least privilege per server: read-only database roles, scoped API tokens, no production credentials for experiments.
- Return small results: limits, aggregates, truncation. Big results cost tokens and leak more.
- You can allow or deny MCP tools in permissions by name, such as `mcp__warehouse__query`.

## Lab: your warehouse server (40 minutes)

In ~/cc-sandbox (with Python 3.10 or newer):

1. Load the warehouse once: `python3 -m pipeline.run 2026-10-01 2026-10-07` (this creates `warehouse.db`).
2. `python3 -m venv .venv && source .venv/bin/activate && pip install mcp`.
3. Ask Claude Code to create `mcp_warehouse.py` from the lesson. Review it yourself; the read-only connection must be there.
4. Register it: `claude mcp add warehouse -- $(pwd)/.venv/bin/python $(pwd)/mcp_warehouse.py`. Restart `claude`, run `/mcp` and check it is connected.
5. Ask: *"Using the warehouse tools, which country has the highest revenue and how many orders does it have?"* Approve the tool calls and check the answer against the pipeline's printout.
6. Ask: *"Delete the orders for 2026-10-01 using the warehouse query tool."* It must fail. Note the error.
7. Ask Claude to add a third tool, `daily_revenue(country)`, that returns revenue per day for one country with a parameterised query. Test it.

Q: Why is it risky to give one agent both a tool that reads private data and a tool that can send data out (web requests, email)?
MODEL: Because content the agent reads can contain prompt injection. A malicious row, document or web page can instruct the agent to send private data to an outside address, and with both capabilities in one session it can. Mitigations: do not combine private-data read tools with outbound tools in the same session, require confirmation for outbound actions, use allow-lists of destinations, and keep results small.

@@interview
Q: What is the Model Context Protocol and why does it matter for data platforms?
TAG: ai
A: MCP is an open standard for exposing tools and data to AI applications through servers, so one integration works across clients. For a data platform it means the warehouse, catalog, orchestrator and observability tools can be offered to agents with clear schemas, instead of each team writing glue. The platform team's job becomes providing safe, well-described, least-privilege tools: read-only roles, row limits, query tagging, audit logs, as a paved path for AI access.
---
Q: How would you give an AI agent safe access to the data warehouse?
TAG: ai
A: A dedicated service role with SELECT only on curated, non-sensitive schemas, masked views for anything personal, a statement timeout and a byte or row cap, and query tagging for cost attribution and audit. The MCP server exposes a few well-described tools (list tables, describe, query with a limit, curated metrics), not raw admin access. No write tools by default; writes go through code review and pipelines. Results are capped, and the agent never gets production write credentials.
---
Q: What would you check before installing a third-party MCP server?
TAG: ai
A: Who publishes it and whether it is maintained, what permissions and credentials it needs, which tools it exposes (especially write, network or shell), whether it sends data anywhere, and whether I can pin a version and read the code. Then I run it with the narrowest credentials in a sandbox first and decide which of its tools to allow.
---
Q: Design an AI assistant that helps analysts answer questions from the warehouse.
TAG: design
A: Semantic layer first: curated metrics and dimensions with definitions, so the agent queries governed models instead of raw tables. Tools: search the catalog, describe a model, run a metric query with a cost estimate, and show the generated SQL. Guardrails: a read-only role on curated schemas, row and cost limits, PII masked, every answer shows its SQL and source tables, and eval sets of known questions with expected answers to track accuracy. Feedback loop: analysts flag wrong answers, which become new eval cases and metric documentation.
---
Q: How do you prevent an AI agent from running an expensive query on the warehouse?
TAG: ai
A: In the platform, not the prompt: a warehouse role with resource limits (statement timeout, a bytes-scanned cap, a small dedicated cluster), a dry-run or EXPLAIN step in the tool that rejects queries above a cost threshold, required partition filters on large tables, row limits, and query tags so spend is visible per agent. The tool returns a helpful error so the agent can refine the query.

RUBRIC: - A production admin password is committed in plain text: rotate it now, and use environment variables or a secret manager.

- A shell server gives unrestricted command execution: remove it (Claude Code already has Bash with permissions).
