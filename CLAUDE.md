# Data Architect: working notes for Claude

A single-user interview-prep PWA for a senior data engineer (Raghavendra). Static files, served by GitHub Pages at https://raghav511.github.io/de-architect/. Used on a MacBook (Chrome), iPad and iPhone (Safari). Keep this file short and current: update it with every PR, and delete anything that is no longer true.

## How we work

- **Ship first, check after.** Build the feature with its own tests, open a PR, merge it at once, then run the long checks in the background (7 simulated users, accessibility, journeys, red team, speed, offline) and ship a fix for anything they find. Never hold a merge for the full suite.
- **Merge PRs yourself; never wait for the user.** If GitHub blocks a merge (a required review on `main`), do not bypass it with `--admin` or change branch protection: tell the user and keep working on the next thing.
- **Decide and continue.** If the user has not answered in 10–15 minutes, pick the recommended option and keep going.
- **The user's feedback mid-task comes first:** do it, ship it, then return to the plan.
- **Fewest taps:** one task per screen, the main action visible without scrolling on a phone, nested tabs instead of long pages, autosave instead of Save buttons.
- **Self-contained:** everything is learned and practised inside the app. Outside sources appear only as small ⓘ/▶ links next to an in-app note, opening in a new tab. No pirated or paywalled copies.
- **Progress is never lost.** Content changes go through the update tracker (below); never delete learner data.
- Show progress as a live checklist (the desktop app's task list) and plain status lines while working.
- Never print or commit the sync URL or its key (`~/.data-architect/config.json`), API keys, or learner data. Tests never reach the real grader on 127.0.0.1:8765.

## Shipping a change

- Version strings: `VERSION` in `js/app.js`, `CACHE` and `?v=` in `sw.js`, `?v=` in `index.html`, and `version.json` (`notes` are shown to the learner as release notes, in plain words).
- The local helper `../qa/ship.sh NEWVER "title" "note" ...` bumps all of them, commits, opens the PR and merges it (it prints `NEEDS YOUR MERGE` if GitHub blocks it). PR descriptions end with the Claude Code line; commits with the Co-Authored-By line.
- Rebuilding the terminal: bump `VMV` in `js/term.js` (the service worker keeps `vm/` in its own cache across app updates).

## Tests

- `node tools/flows.js BASE [filter]`: user journeys (Playwright). `node tools/a11y.js BASE`: axe, light and dark. `node tools/sched_test.js BASE`: scheduler.
- `node tools/personas/run.js BASE OUT [id]`: 7 simulated users rated 1–10 with P0/P1/P2 issues (needs fake sync and the stub grader; `../qa/round.sh OUT [id]` starts them).
- `python3 tools/build_bank.py`, `python3 tools/validate.py`: banks and content (need duckdb 1.5.x; 2.0 breaks minispark).
- `node tools/vm/labs_test.mjs`: boots the in-app Linux headless and passes all 16 Git labs.
- `../qa/checks.js BASE`: red team, broken-state recovery, offline, speed and size budget against `../qa/perf_baseline.json` (use the gzip server on 8812 for realistic sizes).
- Known failing: `persona: Python runtime unreachable shows a clear error` (pre-existing).

## Key mechanisms

- **Scheduler:** units are packed day by day from today; nothing is skipped. Days since `S.since` (first use or "Make this week 1") with nothing done count as missed and show a "Catching up" note. Main-path steps come before Claude Code steps on the same day.
- **Update tracker:** each step, exercise and quiz has a content fingerprint (`S.cv`). When content you finished changes, the step goes back to not done with an "Updated" tag, and the old completion, score and code move to `S.archive`. New modules and steps are listed in the one-line "What is new" note on Today. `repairTracker()` fixes damaged tracker data.
- **Saving:** `save()` writes after 150 ms and flushes on pagehide or hidden; `saveT` is reset after each write.
- **Profile:** the avatar at top right opens `#/profile`: one-tap Sync, Update and Mode, then tabs Sync, Look, Plan, AI, Data that autosave.
