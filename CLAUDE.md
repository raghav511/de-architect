# Data Architect: working notes for Claude

A single-user interview-prep PWA for a senior data engineer (the learner; who they are lives only in `~/.data-architect/profile.txt`, never in this public repo). Static files, served by GitHub Pages at https://raghav511.github.io/de-architect/. Used on a MacBook (Chrome), iPad and iPhone (Safari). Keep this file short and current: update it with every PR, and delete anything that is no longer true.

## How we work

- **Ship first, check after.** Build the feature with its own tests, open a PR, merge it at once, then run the long checks in the background (7 simulated users, accessibility, journeys, red team, speed, offline) and ship a fix for anything they find. Never hold a merge for the full suite.
- **Merge PRs yourself; never wait for the user.** If GitHub blocks a merge (a required review on `main`), do not bypass it with `--admin` or change branch protection: tell the user and keep working on the next thing.
- **Decide and continue.** If the user has not answered in 10–15 minutes, pick the recommended option and keep going.
- **The user's feedback mid-task comes first:** do it, ship it, then return to the plan.
- **Fewest taps:** one task per screen, the main action visible without scrolling on a phone, nested tabs instead of long pages, autosave instead of Save buttons.
- **Self-contained:** everything is learned and practised inside the app. Outside sources appear only as small ⓘ/▶ links next to an in-app note, opening in a new tab. No pirated or paywalled copies.
- **Progress is never lost.** Content changes go through the update tracker (below); never delete learner data.
- Show progress as a live checklist (the desktop app's task list) and plain status lines while working.
- Never print or commit the sync URL or its key (`~/.data-architect/config.json`), API keys, or learner data. Tests never reach the real grader on 127.0.0.1:8765.
- **Security review 11–13 (hardening):** grading through the sync script checks on a back-off (5, 10, 20, 40 s then each minute, `GRADE_BACKOFF`), at most 8 checks per answer (`g.checks`, then one per 10 minutes on reopen) and none while the tab is hidden (`waitVisible`); `sync/Code.gs` refuses every request when `KEY` is empty unless a valid session comes with it (`NO_KEY`, the app explains it), and has `authorize()` for the one-time UrlFetch permission; CSP `connect-src` lists only self, script.google.com, script.googleusercontent.com, accounts.google.com, cdn.jsdelivr.net and the Mac grader; Settings accepts only `https://script.google.com/macros/s/…/exec` sync URLs (or localhost). Test browsers use `bypassCSP` for stub hosts such as https://sync.test; Q24 and Q35 run with the policy enforced. Tests Q33–Q35.
- **No API key in the browser (2026-11-08, user's decision):** every page on raghav511.github.io can read this origin's storage, so the app never stores or uses an AI key: the coach, live mock and grading go only through Claude Code on the Mac (`macCall`, the grader directly or through Sync), or AI is off. `dropAiKey()` deletes a key (and `aiModel`) left by an older version on load (written back to storage at once), after a restore and on every write, and maps an old `coachVia: 'key'` to `mac`; Profile › AI has no key field; the CSP has no api.anthropic.com (Q42). Tests stub the Mac route by replacing the page's `macCall`, never the real grader.
- **Public repo security:** `tools/secret_scan.py` runs in the pre-commit hook, `../qa/ship.sh` and `tools/refresh/ship.sh` and blocks keys, sync URLs, emails, home paths and the words in `~/.data-architect/private_terms.txt`. Who the learner is lives only in `~/.data-architect/profile.txt` (grader and coach read it). Commits use the GitHub noreply email. `index.html` has a Content-Security-Policy (scripts only from the app and cdn.jsdelivr.net, nothing inline, no frames); keep new code free of inline scripts and `eval`. Grader practice runs may read only inside their sandbox copy (`RUN_ALLOW`).

## Shipping a change

- Version strings: `VERSION` in `js/app.js`, `CACHE` and `?v=` in `sw.js`, `?v=` in `index.html`, and `version.json` (`notes` are shown to the learner as release notes, in plain words).
- The local helper `../qa/ship.sh NEWVER "title" "note" ...` bumps all of them, commits, opens the PR and merges it (it prints `NEEDS YOUR MERGE` if GitHub blocks it). PR descriptions end with the Claude Code line; commits with the Co-Authored-By line.
- `../qa/ship.sh` always works in the main checkout; from a worktree or another clone use `tools/refresh/ship.sh` (same steps, in its own checkout).
- Rebuilding the terminal: bump `VMV` in `js/term.js` (the service worker keeps `vm/` in its own cache across app updates).

## Tests

- `node tools/smoke.js BASE [filter] [--engine chromium|webkit]`: every feature once, as the learner uses it, on Chromium (Mac) and WebKit (iPhone 13): reel sound and moving on, Python output, quiz score, live mock score, simulator grade, sync merge, every section opening, figures, search, warm-up, profile, offline, terminal. Run it before shipping and against the live site after. Playwright's WebKit cannot decode AAC, route requests under a service worker, or reload offline, so real Safari is checked in the iOS Simulator (`xcrun simctl boot`, then open the live URL; Safari's speaker icon shows the recording playing).
- **Tests never wait on the internet:** `tools/smoke.js`, `tools/qa_trust.js` and `tools/flows.js` call `blockExternal(context)` (`tools/testnet.js`) first, so every outside host a test does not stub is refused at once (a DNS outage on fonts.googleapis.com or accounts.google.com used to time out every smoke page); only cdn.jsdelivr.net (Pyodide, marked) is reached for real. Add stubs after it: the newest route wins. New test files with a browser context should call it too.
- `node tools/flows.js BASE [filter]`: user journeys (Playwright; `sim` runs the simulator ones, `loop` the interview loop ones). `node tools/sim/engine_test.js`: simulator scenarios. `node tools/qa_trust.js BASE [filter]`: 44 trust and data-safety cases (Q01–Q42, Q51, Q52); run it before every ship. `node tools/a11y.js BASE`: axe, light and dark. `node tools/sched_test.js BASE`: scheduler.
- `node tools/crawl.js BASE [--engine chromium|webkit] [--state fresh|mid] [--quick] [--only REGEX]`: the button crawler. Visits every screen (NAV, NAV_GROUPS, every module tab, practice tabs, a problem of each kind, quiz, live mock, reels, simulator and its modes, warm-up, Profile, terminal) on Chromium (Mac) and WebKit (iPhone 13), first run and five weeks in, clicks every control once from the same starting state and records what happened, errors, CSP violations, dead controls, tap targets under 44 px, overflowing text and unnamed controls; destructive controls are skipped and listed. Regression checks for the bugs it found are in `REGRESS`. All four runs write `tools/crawl/REPORT.md`; `tools/crawl/UX.md` is the Mobbin benchmark.
- `node tools/personas/run.js BASE OUT [id]`: 7 simulated users rated 1–10 with P0/P1/P2 issues (needs fake sync and the stub grader; `../qa/round.sh OUT [id]` starts them).
- `python3 tools/build_bank.py`, `python3 tools/validate.py`: banks and content (need duckdb 1.5.x; 2.0 breaks minispark). A new bank problem gets its expected values checked against a brute force, tests that catch the usual wrong answers (unsorted input, ties, boundaries, greedy), and a large-input test where a slow approach would pass the small ones; `../qa/CODING-REVIEW.md` has the coverage table.
- `node tools/vm/labs_test.mjs`: boots the in-app Linux headless and passes all 16 Git labs.
- `node tools/perf/measure.js BASE [--engine chromium|webkit] [--runs 3] [--only load,actions,memory]`: speed on a mid-range phone (Pixel 5 with 4x CPU slowdown in Chromium, iPhone 13 in WebKit), both over the same shaped Fast 4G line (`tools/perf/net.js`, service worker requests included; local runs take Google Fonts from a fetched copy); medians of 3. `node tools/perf/budget.js BASE` fails if an item in `tools/perf/budget.json` is more than 10% over budget.
- `../qa/checks.js BASE`: red team, broken-state recovery, offline, speed and size budget against `../qa/perf_baseline.json` (use the gzip server on 8812 for realistic sizes).

## Key mechanisms

- **Today:** one box called Today with three tabs named after the app's groups (user's F2 and F8), each showing its minutes: Learn (`grp-hour`: Reading and labs, Quiz, a Reels for today row that ticks itself once a reel is watched today), Practice (`grp-coding`: a Design, build and Git section `grp-build` with the design problem, project sessions, Git labs, drills and a simulator challenge row `simTodayItem` when the day's build minutes have room, then the Coding track) and Interview (`grp-interview`: the module's interview set `grp-talk`, Interview practice with a written mock link, then Coaching). Tabs only group what is shown; the minutes come from the lanes below. Each part has its own daily minutes (`budgets()`: reading `capWd/capWe` 60/120, design and build `buildWd/buildWe` 30/60, coding `codeWd/codeWe` 50/80, interview and coaching `ivWd/ivWe` 40/55 (10 more than before 2026-11-08 for the loop drill), all in Profile › Plan and synced with `PREF_KEYS`; an open company question always keeps one 5-minute row), filled by `fill()`, so carried work never lengthens a day. Reading keeps program order; an unfinished earlier module shows first in its own "Finish … first" block; a step carried from an earlier day is tagged "from Mon" (`S.planned`). Coding: reviews due, today's set (on a set's last one to three days also a Hard stretch DSA problem, `st: 1` in `tools/bank_dsa.py`, kept out of the 84-day ladder), then this week's leftovers; an earlier week's unsolved problems wait for the weekend catch-up block (`codingItems`). Interview: the mock (its blanks carry into the next mock only on the same module, `mockQuestions`), the day's interview loop drill (`loopTodayItem`, ticks itself when that round is practised today), coach items, then company questions with this module's first (`interviewItems`). Manual ticks live in `S.xdone[date]`; company questions tick on `#/recent`.
- **Daily refresh:** `tools/refresh/ROUTINE.md` (run every evening at 9 PM by the scheduled task `data-architect-weekly-refresh`, renamed Data Architect daily refresh; it adds interview questions, news, coding problems, design questions and module edits, then writes and records reels for new or changed sections in `~/.data-architect/refresh-repo`; companies in `tools/refresh/companies.txt`; ships with `tools/refresh/ship.sh`).
- **Recent interview questions:** `data/recent.json` (items: id, mid, company, level, asked, found, TAG, Q, A, src, url), written by the weekly scheduled task `data-architect-weekly-refresh` (also refreshes `data/news.json` and module content). Shown at `#/recent`, on the module's interview page, as one Today row (until every new one is ticked in `S.rq`) and in What is new. They are part of the interview step's fingerprint, so a finished interview step goes back to not done when its module gets new questions. Got it on What is new only hides the note; nothing is ever marked done for the learner. `tools/validate.py` fails when two ids carry the same question text (ignoring case, markdown and punctuation): keep one.
- **Module tabs:** a tab is finished when `S.tabs[m:tab]` is set (with the text's hash; a changed tab is not finished) ("Done, next") or all plan steps that open it are ticked (`tabDone`); `#/learn/m` opens the first unfinished tab.
- **Scheduler:** units are packed day by day from today; nothing is skipped. Design problems and project sessions (`isBuild`) run in their own lane against `budgets().build` (`sc.bused`), in program order and never before their module's first reading day; reading days count reading only (`sc.used`). Days since `S.since` (first use or "Make this week 1") with nothing done count as missed and show a "Catching up" note. Main-path steps come before Claude Code steps on the same day.
- **Update tracker:** each step, exercise and quiz has a content fingerprint (`S.cv`). When content you finished changes, the step goes back to not done with an "Updated" tag, and the old completion, score and code move to `S.archive`. New modules and steps are listed in the one-line "What is new" note on Today. `repairTracker()` fixes damaged tracker data.
- **Udemy links:** `udemyLinks()` shows a folded "Watch on Udemy" list under D1's chapter sections (`modules.d01.sections`, keyed by chapter h2 index), one row at the top of P1–P5's chapter (`modules.pX.lectures`), and on DSA problems by week (`dsa.weeks`). The lessons themselves are written for the app; never copy course material. No separate Udemy modules: content goes into the module and week already in the schedule.
- **Architect's lens:** a chapter h2 containing "Architect's lens" is wrapped in a `.lens` card by `mdEl()`: a 7-row table (what problem, why over others, when not, who owns and pays, where it sits, how it fails and scales, when to move off) and "Under the hood" internals questions with `<details>` model answers; matching questions join the module's `@@interview`. One per technology, in the week it is taught: P1.8 Python, 1.9 Airflow (data intervals and backfills, DAG parsing cost, deferrable operators, Celery or Kubernetes executors, Airflow 3), 2.9 Iceberg and open table formats (metadata tree, commits, hidden partitioning, copy-on-write vs merge-on-read, compaction and snapshot expiry, v3 deletion vectors; v3, S3 Tables and REST catalogs such as Polaris in the table; 8.5 links to it), 3.10 Spark (driver, DAG, stages and tasks; shuffle cost, broadcast and AQE; skew and salting; executor memory, spill and OOM; Catalyst and whole-stage codegen, each with the version it arrived in; a What changed in Spark 4 block: Spark Connect, ANSI on by default, VARIANT; three quiz questions too), 4.10 dbt (what dbt run does, incremental models and late data, slim CI, snapshots, tests and contracts), M1.8 dimensional modelling (why stars are fast, fan traps, late dimension rows, SCD2 point-in-time joins), 5.9 Kafka (why fast on disk, acks and ISR, rebalances, exactly-once, KRaft and tiered storage), D1.9 Postgres (MVCC, vacuum and wraparound, WAL and replication slots, planner statistics, GIN/BRIN/partial indexes, poolers, declarative partitioning; vs MySQL, distributed SQL and a warehouse; answers link to D1's figures), 5.10 Flink and streaming engines (checkpoints and barriers, two-phase commit sinks, watermarks and late data, state backends and RocksDB, Flink 2.0 disaggregated state, backpressure tied to the simulator's partitions and hot key challenges; three quiz questions too), 6.9 Debezium and CDC (log-based vs query-based, triggers, dual writes and the outbox, managed CDC; replication slots and WAL retention, incremental snapshots, keys and LSN order, schema changes through the registry, idempotent MERGE into the lakehouse, the slot that fills a disk at 3 a.m.; linked to the simulator's cdc, schema and region challenges; three quiz questions too), 8.8 Snowflake and Databricks (pruning, clustering and search optimization, warehouse credits and the three caches, Time Travel and clones, Photon with deletion vectors and liquid clustering, Unity Catalog and serverless versus classic, which to pick over Iceberg on Trino; GA marked per feature), O1.9 data mesh and data products, O2.9 golden paths and self-serve templates; each also gets its four-level reels (hand-written into `tools/reels/auto/<mid>.json` with `write.py`'s section hash, then `build.py`). A New this week box may land inside a lens (`freshPlace` best match), so tests count `details:not(.fresh)`. Reel chip `icon`s render as literal text: use a symbol (✓ → ⇉ !), not a word. A chapter links to one of its own figures with `[text](#fig-NAME)`: `FIGS.mount` gives each figure the id `fig-NAME`, and `mdEl` scrolls to it without changing the route. Phone view stacks the rows.
- **Live mock:** Today's interview row opens `#/live/DATE` (the written mock stays at `#/mock`; either ticks the row). Weekdays 20 min, 5 questions: concept, under the hood (the chapter's `### Under the hood` blocks and why/how warm-ups), architect's lens (`TAG: arch` or a staff `defend`), a staff slot by weekday (`LIVE_ROT`: Mon scale, Tue page, Wed defend, Thu metric, Fri lead) and recall from an earlier module. Weekends 35 min, 7 questions: concept, org, migrate, cost, estimate, deep and recall, in a rotating company style. Questions come from the week's modules (`liveWeekMods`). The interviewer (`macCall('chat')`, Claude Code on the Mac) asks one follow-up and scores correct/depth/trade/clear 1–4 plus three staff checks (rejected, limits, operate); with AI off or on error you mark yourself. Answers under 2.5 or skipped open the next live mock on the same module (at most 2). State `S.live[date]`. The nightly coach digest shows the last finished live mock's scorecard (`live_scorecard` in `tools/coach/coach.py`, same maths as `liveCard`; test `python3 tools/coach/scorecard_test.py` on a made-up state).
- **New this week in sections:** `freshFor(m)` gathers What is new items (`data/news.json` `mid`, `sec`) and the module's open company questions (`recent.json`); `freshPlace` puts each under the `## ` heading whose number equals `sec`, else the section whose text matches best, else the chapter top, as a folded amber `details.fresh`. The weekly routine now writes `sec` for both.
- **Fun layer:** `gameXP()` sums done steps (`XP_KIND`), solved problems by level, live and written mocks, warm-up results and ticked company questions. `LADDER` levels from Intern to Architect; Staff, Principal and Architect also need a weekend boss round (live mock, `kind: 'we'`, at staff level) averaging 3.0/3.3/3.5, scored by AI (honest ladder, review 5): each answer records `by` ('ai', 'self'; `liveBy()` reads older answers from `x.self`), a round with any self-marked answer still gives XP but never promotes (`bossBest(level, any)`), and `gameGateText` says why on the ladder (Q52). Recall gives 2 XP per item recalled. Streak days come from `S.doneAt`, live and written mocks, ticked questions and `S.game.days` (`gameNote()` on step, solve, warm-up, live mock); one missed day a week is frozen. Desktop Today shows `gameStrip()`; phones show `gameMini()` in the Today heading (keeps Up next above the tab bar), and the full strip is on Progress. Card of the day sits below the plan. `gameShipCheck()` celebrates a module once (`S.game.shipped`). Profile › Look: Celebrations (default on, off also under reduced motion) and Sounds (default off).
- **Reels:** tab bar Today, Reels, Path, Coding, Projects, More (Design moved to More). `#/reels` plays the feed (`reelQueue`: today's reading sections, the week's modules, then reviews due); `#/reels/ID` plays a module from that reel. A `.rsec` button sits right under every chapter heading; Today has a Reels for today card below the plan. The player is a full-screen card: tap left or right to step, swipe or arrow up and down for the next reel, captions always on, voice from the device (`reelVoices` ranks Premium and Enhanced first; picker with Try). End card: quick check (a miss schedules a review in 3, then 7 and 21 days; `S.reels`) and a work list saved to `#/playbook` (`S.playbook`). XP: 3 per reel, 2 per right check.
- **Reel narration:** hand-written reels play recorded audio, one AAC file per beat in `audio/reels/` (`<id>-<beat>-<hash>.m4a`, about 4 KB a second), made by `tools/reels/voice.py` with Kokoro (open source, on the Mac, voice `af_heart` "Heart", chosen by the user over OpenAI, ElevenLabs, Google and Microsoft). Kokoro lives in `~/.data-architect/kokoro` (venv with kokoro-onnx and soundfile, plus `kokoro-v1.0.onnx` and `voices-v1.0.bin`); the script re-runs itself with that venv. `build.py` keeps links to recordings that still match the text. A beat without a recording (or whose recording fails) is read by the best device voice unless voice is off; it is never silent (Q23). `--engine openai` remains as an option (key in `~/.data-architect/config.json`).
- **Reel writer:** `tools/reels/write.py` writes four-level series (about 5 cents and 30 seconds a section with sonnet) for every chapter section without a hand-written four-level series through `claude -p` on the Mac (tools off, JSON schema), fingerprinting each section so only new or changed ones are rewritten, into `tools/reels/auto/<mid>.json`; `build.py` merges them (a hand-written series with levels wins; a single hand-written reel without levels gives way to the written series). `build.py` also puts every picture in the shape `js/reelfx.js` draws (a flow given as steps or nodes becomes items) and fails on any it cannot draw; in the app `FX.build` turns a picture it cannot draw into a plain caption card, a failing animation step is skipped, and `reelsFor` drops reels without beats (`reelPlayable`), because the player also renders the neighbouring reels and one bad picture used to stop the feed with a page error (Q41). It needs the Mac's Claude Code login (`claude` then `/login` in Terminal); the daily refresh writes the reels itself if that login fails.
- **Speed:** every `<script>` in `index.html` is `defer`: the meta Content-Security-Policy turns off the browser's look-ahead downloads, so plain scripts came one after another (keep `defer` on new scripts, and keep their order). `schedule()` is cached (`SCHED`), keyed on the day, plan settings and ticks, and flushed by `route()` and `save()` (`schedFlush`); call `scheduleNow()` only for a forced fresh plan. `data/reels.json` (megabytes) starts downloading only after the first screen is drawn (`reelsGo()` after the first `route()`; `DATA.reelsP`, awaited by `reelsFor`), so it never shares the line with what Today needs; every other start-up file downloads at once (`loadData`, and `loadModules` fetches the module files alongside the small data files). Budgets and the measured baseline are in `tools/perf/BASELINE.md`. Reel recordings are cache-first in their own service worker cache (`AUDIO`), kept across updates, with Safari's range requests answered from the copy.
- **Reel player look (F3–F6, Instagram-style):** one dark frame from the first frame (`reelFrame`: close, Reels title, My week/Shuffle as text tabs, count): while `data/reels.json` downloads it shows a spinner and skeleton (`reelLoading`, no white page), and the empty state lives in it too. In a reel the picture fills the middle, level, title, module line and caption sit bottom-left on a scrim (`.rinfo`), Save, Speed and Voice are labelled outline icons on the right (`RI`, `.ricon`, 56 px), a thin progress line runs along the bottom, and paused reels show a round translucent play button (`playBig`, still `.rstart`). Speed opens a sheet with `REEL_SPEEDS` 0.25× to 2× (`reelSpeedSheet`, `S.settings.reelSpeed`).
- **Reels feed:** a vertical scroll-snap feed (`reelPlayer`): the slide in view plays, others are stopped; only neighbours are rendered; the next reel's first recording is fetched ahead. Order: Shuffle by default (`S.settings.reelMode`; concepts in random order, the levels of one concept together), or My week (today's reading, the week, reviews, then the next modules); Shuffle filters by everything, weak spots, done before or track.
